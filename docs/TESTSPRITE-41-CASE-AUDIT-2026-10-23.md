## Decision rules

1. **Execution proof is not risk inference.** \`VERIFIED_FAIL\` in the vulnerable first-party harness correctly means that a deliberately flawed fixture violated its invariant. A test runner showing green for reproducing this failure is not evidence of a good payment implementation.
2. **Do not change SQL deadlock HIGH → MEDIUM** merely to match autogenerated expectations; a circular wait graph is objectively observed in the bounded simulation. Severity depends on a documented scoring policy and the measured downstream impact.
3. **Never fabricate GitHub PR findings.** An unrelated or clean patch does not become a critical race merely because it is named "sample".
4. **Unsupported JWT check remains unsupported.** A JWT \`none\` code snippet can be statically flagged as POTENTIAL, but without an executable, authorized authentication target the app must not pretend a live attack or signature-verification action happened.
5. **The UI uses dedicated routes intentionally.** \`/lab\` and \`/about\` are supported product behavior; tests should exercise these routes.
6. **Mobile/keyboard blocked states are not proven application regressions.** Preserve Playwright tests and use correctly configured browser execution.
7. **Do not assume TestSprite's model-generated "fix prompt" proves a Vercel deployment mismatch.** Check actual current commit, Vercel status, and reachable API before acting.
